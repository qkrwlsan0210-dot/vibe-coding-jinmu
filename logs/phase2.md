## 기능 1: 플랜 설정 화면 — 커밋 `65a6416`
- 요청 원문: `페이즈 2이동` → AI가 기능 순서·기능 1 계획 제시
- 진무 결정: 입력칸 예시값 채워두기(13:00 / 08:00 / 30분 / 8시간) · 현재=목표 저장 허용 · 계획 승인
- 구현: 입력 4개(현재·목표 기상, 이동 폭 1~180분, 수면 시간 3~14시간), 입력칸 아래 오류 표시, localStorage `sleepPlan` 저장, 첫 실행 시 설정 화면 → 저장 후 오늘 화면(자리만), 플랜 수정·취소
- 확인한 것 (헤드리스 Chromium, 360px, Asia/Seoul): 첫 실행 흐름, 기본값, 잘못된 입력 9가지(0·181·2.5·빈칸 분, 2시간·14시간1분·60분·빈칸 시간, 빈 기상 시각) 저장 차단+메시지, 경계값(180분·14시간) 저장, 현재=목표 저장, 수정 시 저장값 불러오기, 취소 시 저장값 유지, 새로고침 후 오늘 화면. 콘솔 오류 없음.
- 확인하지 않은 것: 실제 휴대폰(시각 입력 UI는 기기마다 다름), 오늘 화면 내용(기능 2)

## 기능 2: 오늘 화면 — 커밋 `97b80f2`
- 계획 확인 요청 원문: `진행해`
- 구현: 다음 기상 = 현재 기상에서 이동 폭만큼 목표 쪽(짧은 방향), 다음 취침 = 다음 기상 − 수면 시간, 목표까지 N일 = 올림(차이/이동 폭). 현재=목표면 "목표 도달".
- AI `[가정]`: 차이가 정확히 12시간이면 앞당기는 방향.
- 확인한 것 (헤드리스 Chromium, 360px, Asia/Seoul): 계산 8가지 모두 기대값 일치 — 기본 예시(13:00→08:00, 30분, 8h → 04:30/12:30/10일), 취침 자정 넘김, 남은 차이<이동 폭, 늦추는 방향, 자정 넘어 짧은 쪽, 정확히 12시간, 현재=목표, 나눠떨어지지 않는 이동 폭(45분 → 7일). 새로고침 유지, 플랜 수정 반영. 콘솔 오류 없음.
- 확인하지 않은 것: 실제 휴대폰. 기준이 아직 '플랜의 현재 기상 시각'으로 고정(기능 3에서 실제 기록 기준으로 변경).
- 스크린샷: 기능2-1_오늘화면.png, 기능2-2_목표도달.png

## 기능 3: 기상 체크와 재계산 — 커밋 `d0d3d84`
- 구현(CLAUDE.md 그대로): 오늘 화면에 실제 기상 시각 입력 1개(기본값=지금 시각) + "일어났어요" 버튼(탭 1번). 다음 목표 = 마지막 실제 기상 시각 + 1단계. 마지막 기록 1개만 저장.
- 규칙에서 도출(질문 안 함): 같은 시각을 두 번 눌러도 기준이 같아 결과 동일 → 중복 처리 불필요.
- AI `[가정]`: 플랜을 새로 저장하면 실제 기록을 지우고 새 플랜의 '현재 기상 시각'부터 시작(취소하면 유지).
- 확인한 것 (헤드리스 Chromium, 360px, Asia/Seoul, 시계 12:47 고정): 13개 시나리오 — 기본값=지금 시각, 지금 기록, 두 번 누름, 목표대로 기록(9일), 늦잠 14:00 재계산(12일), 남은 차이<이동 폭, 목표 도달, 자정 넘은 01:30 기록, 새로고침 유지, 빈 시각 오류, 플랜 수정 취소 시 기록 유지, 플랜 저장 시 초기화. 모두 기대값 일치, 콘솔 오류 없음.

## 기능 4: 유지 단계 — 커밋 `d7bb4a0`
- 구현(CLAUDE.md "목표 도달 시 유지 단계, 매일 같은 목표"): 목표 도달 시 "목표 도달 · 유지 단계" 표시. 계산 규칙은 기능 3과 동일하므로 늦잠 시 자동으로 다시 목표까지 N일로 돌아감.
- 확인한 것: 09:00→08:00 플랜에서 08:30→08:00→08:00(유지)→08:40(목표까지 2일)→08:10→08:00(유지). 기능 2 계산 8개·기능 3 시나리오 재실행 통과(문구 변경분 제외). 콘솔 오류 없음.
- 확인하지 않은 것: 실제 휴대폰, GitHub Pages 배포 후 동작.
