## 기능 1: 플랜 설정 화면 — 커밋 `65a6416`
- 요청 원문: `페이즈 2이동` → AI가 기능 순서·기능 1 계획 제시
- 진무 결정: 입력칸 예시값 채워두기(13:00 / 08:00 / 30분 / 8시간) · 현재=목표 저장 허용 · 계획 승인
- 구현: 입력 4개(현재·목표 기상, 이동 폭 1~180분, 수면 시간 3~14시간), 입력칸 아래 오류 표시, localStorage `sleepPlan` 저장, 첫 실행 시 설정 화면 → 저장 후 오늘 화면(자리만), 플랜 수정·취소
- 확인한 것 (헤드리스 Chromium, 360px, Asia/Seoul): 첫 실행 흐름, 기본값, 잘못된 입력 9가지(0·181·2.5·빈칸 분, 2시간·14시간1분·60분·빈칸 시간, 빈 기상 시각) 저장 차단+메시지, 경계값(180분·14시간) 저장, 현재=목표 저장, 수정 시 저장값 불러오기, 취소 시 저장값 유지, 새로고침 후 오늘 화면. 콘솔 오류 없음.
- 확인하지 않은 것: 실제 휴대폰(시각 입력 UI는 기기마다 다름), 오늘 화면 내용(기능 2)

## 기능 9: 앞당기기/미루기 비교·선택 — 커밋 `a4d0435` (CLAUDE.md 포함)
- 요청 원문: `지금은 취침시간을 앞당기는 방식이지만 뒤로 미루는 방식도 있잖아. 이것이 기간에 따라 서로 장단점이 있을텐데 미루는 방식과 앞당기는 방식의 차이를 보여주고 선택하게 해줘`
- 질문 없이 구현 (직전 "우선 만들어" 흐름 반영). AI가 정한 것 — 진무 확인 대상:
  - 비교 항목: 총 이동, 하루 이동, 낮(08~18시)에 자는 날 수, 완료일, 장단점 한 줄.
  - 경고 기준: 앞당기기 하루 30분, 미루기 하루 3시간 초과 시 빨간 글씨. 장단점 문구(생체시계 24시간보다 김, 시간요법 1~3시간)는 AI가 일반 지식으로 작성 — 출처 확인 안 함.
  - 기본 선택 = 이동 거리 합이 짧은 쪽.
- 구현 중 AI가 발견해 고친 것: 기존 "N번째 줄 = 적용일 + N−1" 날짜 방식은 하루 이동이 크면(예: 미루기 5일, 하루 3시간 이상) 다음 취침이 이전 기상보다 먼저 오는 모순이 생김 → 기상 시각을 절대 시간으로 이어 붙여 실제 기상 날짜로 표시. 결과: 미루기 5일 계획은 10/14가 빠지고 완료일 10/17(5번 자고 6일째).
- 확인한 것: 06:00/15:00 → 23:00/09:00, 10/12 기준 14·5·3일 비교 수치, 방향 선택 → 완료일·일정 반영, 수정 시 선택 유지, 같은 패턴이면 숨김, 목표가 더 늦으면 기본 미루기, 기존 테스트(14일·1일·연말) 동일 결과. 데모 Version 7 동일. 콘솔 오류 없음.
- 확인하지 않은 것: 실제 휴대폰, 장단점 문구의 학술적 근거.

## 기능 10: 진무가 보여준 화면 방식으로 방향 비교 — 커밋 `f9c7776` (CLAUDE.md 포함)
- 요청 원문: (참고 화면 캡처 첨부, `logs/진무_참고화면_방향비교.png`) `이런 방식을 원한거야`
- 맥락: 기능 9에서 AI가 만든 비교(글자 위주 목록, 같은 기간 기준)는 진무가 원한 형태가 아니었음 — 말로 된 요구("차이를 보여주고 선택하게")만으로는 화면 형태가 전달되지 않았고, AI는 묻지 않고 자기 방식으로 구현함.
- 구현(참고 화면을 따름): 카드 2개(앞으로 당기기 / 뒤로 미루기) — 설명, 작은 원, 걸리는 날·낮에 자는 날·옮길 거리, 미리보기 막대(지금·첫날·2·3일째·…·마지막), 장단점 점 3줄, 추천 배지, 추천 이유 문장. 아래 기간 슬라이더 + 걸리는 기간·하루에 옮기는 양·권장/빠름 + 완료일.
- 참고 화면과 다르게 한 것 (AI 판단, 진무 확인 대상):
  - 미리보기 이름: 참고 화면 "오늘·내일·모레·3일 뒤·9일 뒤" → "지금·첫날·2일째·3일째·N일째". 이 앱은 적용 날짜 첫날부터 이미 1단계 이동하므로 "오늘=현재 패턴"과 맞지 않음.
  - 참고 화면 아래 문구 "자는 시간은 그대로 두고 잠드는 때만 옮깁니다"는 넣지 않음 — 이 앱은 현재·목표 수면 시간이 다르면 취침·기상을 따로 옮김.
  - 권장 속도 당기기 30분·미루기 90분은 참고 화면의 −30분/+90분에서 가져옴.
  - 추천 규칙: 낮에 자는 날이 적은 쪽, 같으면 걸리는 날이 적은 쪽.
  - 슬라이더 범위 1~60일.
- 확인한 것: 800px(카드 2열)·360px(카드 1열, 가로 스크롤 없음), 라이트·다크. 기본 예시 수치(당기기 14일·0일·7h / 미루기 12일·7일·17h), 추천·이유 문장, 미루기 선택 시 슬라이더 12일·권장, 7일로 줄이면 "빠름", 일정 생성, 수정 진입 시 유지, 목표가 더 늦은 경우 미루기 추천. 데모 Version 8 동일. 콘솔 오류 없음.
